# notification-service

desyp의 상시 알림 트랙. 사전 등록, 추천 점수와 순위, 이벤트 전 이메일 알림을 담당한다.
공통 코드 규칙은 루트 `CLAUDE.md`, API와 실행법은 이 폴더의 `README.md`를 따른다.

## 현재 제품 정책

- 로그인 제공자는 Google OIDC·네이버 OAuth2를 지원한다.
- 소셜 로그인에서 제공한 이메일을 사용하고 연령 확인·개인정보 수집 동의 후 사전 등록한다.
- **다계정 추가 방지는 제외한다.** 동일 소셜 계정·정규화 이메일 중복 등록은 기존 정책대로 차단한다.
- 추천 코드는 선택 사항이고 등록 완료 시 한 번 연결한다. 등록 후 추천인 변경은 허용하지 않는다.
- A의 코드로 B가 등록 완료하면 A의 실제 추천 인원 수가 1 늘고 B에게 코드 사용 보너스 1점을 부여한다.
- **최종 순위 점수 = 실제 추천 인원 수 + 코드 사용 보너스(최대 1점).** 상품 선정 기준은 **최고 추천 점수**다.
- 링크 클릭이나 실패한 등록은 점수를 주지 않는다. 자기추천과 반복 등록으로 보너스를 다시 받는 것은 금지한다.
- 순위는 `1, 1, 3` 형식의 공동 순위다. 요청한 순위 경계의 동점자를 모두 반환한다. 동점자의 최종 상품 배분은 운영 결정 사항이다.
- 이벤트 시작 1~2시간 전 알림을 발송한다. 정확한 발송 시점·행사 시각·추천 집계 마감은 아직 미확정이다.

## 기술과 배포

- Java 21, Spring Boot, PostgreSQL, Flyway
- 배포 목표: AWS Lambda. 현재 인증은 서버 세션이므로 Lambda/다중 인스턴스의 세션 공유 방식은 배포 전 확정한다.
- Google OIDC는 `openid`, `email`만 요청한다.
- AWS SES 발송, EventBridge Scheduler 예약 실행은 미구현이다.
- 초기 규모: 2개월간 낮고 꾸준한 사전 등록 트래픽. 이벤트 당일 응모 고트래픽은 event-entry-service 책임이다.

## 패키지와 책임

- `subscriber`: 사전 등록·동의·중복 검증, 추천 관계와 보너스 저장
- `auth`: 인증 계정 확인, 관리자 접근 허용 목록
- `referral`: 내 점수와 관리자 추천 순위 조회
- `global`: 세션/CSRF 보안 설정
- `mail`: 후속 SES 발송 구현 예정

공통 `BaseErrorCode`, `BusinessException`, `ApiResponse`, 예외 처리는 `common`을 사용한다.

## 데이터 모델과 점수 집계

`V1__create_subscribers.sql`에 사전 등록 테이블이 있고 `V2__add_referral_bonus.sql`에서 보너스와 제약을 추가한다.
이미 적용된 마이그레이션을 수정하지 말고 후속 버전 파일을 추가한다.

- `provider`, `provider_account_id`: 로그인 제공자(GOOGLE/NAVER)와 제공자별 계정 식별자. 두 컬럼 조합이 UNIQUE다.
- `email`, `email_normalized`: 원문 이메일과 UNIQUE 정규화 이메일
- `referrer_id`: 기존 가입자를 가리키는 자기참조 FK, JPA에서 수정 불가
- `referral_bonus`: 추천인이 없으면 0, 있으면 1. 생성자가 추천 관계로 결정하며 요청 값으로 받지 않는다.
- `invite_token`: UUID 추천 코드, UNIQUE
- `age_confirmed`, `consent_at`, `created_at`: 동의와 생성 기록

실제 추천 인원은 저장된 `referrer_id` 관계를 `COUNT`로 집계한다. 별도의 누적 카운터를 증가시키지 않아 동시 갱신 유실과 카운터 불일치를 피한다.
보너스는 별도 컬럼으로 저장한다. DB CHECK로 추천 관계에 맞는 0/1 값과 자기추천 금지를 검증한다.
V2는 기존 데이터에도 추천인이 있으면 보너스 1점을 소급 적용한다.
조회는 한 SQL에서 추천 인원·보너스·합계 및 순위를 계산하고 트랜잭션 경계는 Service에 둔다.

이메일 정규화: Locale.ROOT 소문자화, `+` 별칭 절삭, Gmail 점 제거, googlemail.com → gmail.com 통합.

## 보안과 운영

- 내 점수 조회는 요청 파라미터의 사용자 ID를 신뢰하지 않고 로그인 계정으로 조회한다.
- 관리자 API는 `ADMIN_GOOGLE_SUBS`에 지정된 검증된 Google 계정만 접근한다. 설정이 비어 있으면 전부 거부한다.
- 순위 응답의 이메일은 상품 연락을 위한 관리자 전용 정보다. 공개 순위 API는 현재 없다.
- 이메일·추천 코드·소셜 식별자를 로그로 남기지 않는다.
- 최종 수상자 확정/순위 스냅샷/상품 지급/부정행위 추가 검증은 현재 API에서 수행하지 않는다.

## 커밋 scope

- `auth`: Google·네이버 인증, 관리자 인증
- `subscriber`: 사전 등록, 프로필, 동의
- `referral`: 추천 관계, 점수, 순위
- `mail`: 발송, 재시도, 바운스 처리

## 검증과 남은 작업

HTTP 보안 필터부터 H2 PostgreSQL 모드 저장과 Flyway V1→V2 업그레이드까지 테스트한다.
실제 PostgreSQL, 외부 Google 로그인, 네이버, SES, Lambda 연결은 별도 환경 검증이 필요하다.
커넥션 풀 부하·운영 인증/세션 구성·메일 발송 이력과 재시도·추천 집계 마감 및 동점 상품 정책은 후속 작업이다.
